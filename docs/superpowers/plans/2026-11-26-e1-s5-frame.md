# E1-S5 Header, mobile menu and footer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A professional header, a dialog-like mobile menu and a clean footer on every page, with search removed.

**Architecture:** `data/headerNavLinks.ts` drives header, menu and sitemap; entries with an `event` are file links rendered as plain `<a>`. The menu stays hand-written in `MobileNav.tsx`: one `open` state, effects for scroll lock, keys and resize, no new dependency.

**Tech Stack:** Next.js 13.4 app router, React 18.2, Tailwind 3.3, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-26-e1-s5-frame-design.md`

## Global Constraints

- Header: About, Résumé (from `sm`, 640px). Menu: Home, About, Résumé. Résumé is `/static/resume.pdf`, new tab, `rel="noopener noreferrer"`.
- Umami: `data-umami-event="resume"`, `data-umami-event-where` is `header` or `menu`.
- Button labels: "Open menu", "Close menu". Dialog name: "Menu". Panel id: `mobile-menu`.
- Footer line: "Enmanuel Veras • © {build year} • everas.dev".
- No new dependency. No visual change beyond the links and removals.
- Don't touch `AuthorLayout`, `data/authors/`, site titles, RSS links or `robots` metadata.
- E2E expected values are written in the test, not imported from `data/`.
- Before each commit: `yarn next lint --dir app --dir components --dir layouts --dir scripts` and `yarn tsc --noEmit --tsBuildInfoFile node_modules/.cache/tsconfig.tsbuildinfo` pass (build first).
- Run tests as `APP_PORT=3105 yarn test:e2e …`.

## Review Focus

1. Browser Back with the menu open: the menu closes and the page scrolls again (Task 3).
2. Tapping blank space in the open menu, then `Tab`: focus returns inside the menu (Task 3).
3. `Esc` with the menu closed: focus doesn't move (Task 3).
4. Selecting the current page's link: the menu still closes (Task 3).
5. A 400px viewport doesn't scroll sideways after the header changes (existing tests in `home-hero.spec.ts` and `credentials.spec.ts`; run the full suite in Task 4).

### Task 3: Mobile menu as a dialog

**Files:**
- Modify: `components/MobileNav.tsx`
- Test: `e2e/frame.spec.ts`

**Interfaces:**
- Consumes: `NavItem`, `headerNavLinks`, `#mobile-menu`, `hydrated(page)`.

- [ ] **Step 1: Write the failing tests** in a `test.describe('FR-17 mobile menu')` at 400×800. Helpers: `menu` = `#mobile-menu`; `opener` / `closer` = buttons "Open menu" / "Close menu"; `overflow(page)` = `expect.poll(() => page.evaluate(() => document.body.style.overflow))`; `focusInMenu(page)` = `page.evaluate(() => !!document.activeElement?.closest('#mobile-menu'))`. Every test goes to `/` and awaits `hydrated`.

| Test | Actions | Assertions |
| --- | --- | --- |
| closed menu is out of reach | press `Tab` 20 times | `aria-hidden="true"`, menu hidden, `focusInMenu` false after each press |
| open menu takes the focus | click opener | dialog "Menu" visible, `aria-hidden="false"`, closer focused, opener `aria-expanded="true"`, overflow `hidden` |
| focus stays inside | open; `Tab` 4 times; then `Shift+Tab` from closer | `focusInMenu` true after each; after the 4th `Tab` closer focused; `Shift+Tab` focuses link "Résumé" |
| blank space then Tab | open; `page.mouse.click(200, 750)`; `Tab` | `focusInMenu` true |
| Escape closes | open; `Escape` | `aria-hidden="true"`, opener focused, overflow `''` |
| Escape does nothing when closed | focus "Toggle Dark Mode"; `Escape` | it stays focused |
| close button closes | open; click closer | same as Escape |
| link closes | open; click "About" | URL `/about`, `aria-hidden="true"`, opener focused, overflow `''` |
| current page link closes | open; click "Home" | `aria-hidden="true"`, overflow `''` |
| résumé closes | `context.route('**/static/resume.pdf', r => r.fulfill({ contentType: 'text/html', body: 'pdf' }))`; open; click "Résumé" while awaiting `popup` | popup URL ends `/static/resume.pdf`, `aria-hidden="true"`, opener focused |
| Back closes | open; click "About"; open; `page.goBack()` | URL `/`, `aria-hidden="true"`, overflow `''` |
| widening closes | open; viewport 800×800 | `aria-hidden="true"`, overflow `''` |

- [ ] **Step 2:** Build and run the spec. Expected: the new tests FAIL (no "Open menu" button).
- [ ] **Step 3: Implement** in `MobileNav.tsx`:
  - `const [open, setOpen] = useState(false)`; `close()` sets `false` and focuses the menu button. Buttons, links and `Esc` use it.
  - Panel: `role="dialog"`, `aria-modal="true"`, `aria-label="Menu"`, `aria-hidden={!open}`. Open classes `visible translate-x-0 transition-transform`; closed `invisible translate-x-full transition-[transform,visibility]`. Visibility must not transition on opening, or the close button can't take focus.
  - One effect while `open`: focus the close button, set `body` overflow `hidden`, listen for `keydown` on `document` (`Escape`; `Tab` wraps across the panel's `a[href], button`, and pulls outside focus back in) and for `matchMedia('(min-width: 640px)')` changes (close without moving focus). Cleanup removes both and resets overflow to `''`.
  - A second effect closes the menu when `usePathname()` changes.
- [ ] **Step 4:** Rebuild and rerun. Expected: PASS.
- [ ] **Step 5:** Lint, type check, commit `feat(frame): make the mobile menu behave like a dialog`.
